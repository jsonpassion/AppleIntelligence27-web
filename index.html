§1

개요 — 이번 세대가 바꾸는 것

2025년의 Foundation Models 프레임워크가 "온디바이스 Apple 모델을 세 줄의 Swift로 호출한다"는 증명이었다면, 2026년 6월 8일 발표된 3세대는 그 API를 플랫폼으로 확장합니다[1][2]. 핵심 변화는 세 가지입니다.

첫째, 모델이 교체 가능한 부품이 됐습니다. 새 LanguageModel 프로토콜 아래에서 온디바이스 모델, Apple 서버 모델(PCC), Anthropic Claude, Google Gemini, 로컬 오픈소스 모델(Core AI · MLX)이 전부 같은 LanguageModelSession으로 호출됩니다. 세션 코드는 그대로 두고 모델만 갈아 끼울 수 있습니다[2][5][11].

둘째, Apple 서버 모델이 개발자에게 열렸습니다. 계정도, API 키도, 과금 설정도 없이 PrivateCloudComputeLanguageModel() 한 줄로 32K 컨텍스트 서버 모델을 호출하고, 첫 다운로드 200만 미만 앱은 무료입니다[2][4][8].

셋째, 에이전틱 앱이 1급 시민이 됐습니다. 상태에 따라 지시문·도구·모델을 선언적으로 교체하는 Dynamic Profiles, Vision 기반 내장 도구(OCR·바코드), Spotlight 시맨틱 인덱스를 이용한 완전 로컬 RAG, 품질을 정량 측정하는 Evaluations 프레임워크, 에이전트 전용 Instruments까지 — 설계·구현·디버깅·평가의 전 과정을 커버하는 도구가 한 세대에 모두 나왔습니다[2][3][7][15].

시점 주의 — 이 문서는 2026년 7월 12일, OS 27 베타 기준으로 작성됐습니다. 정식 릴리스(2026년 9월 예정) 전까지 API 시그니처와 정책 수치는 변경될 수 있습니다.

Instruction-Following Pruning — 20B를 폰에 넣는 방법

AFM 3 Core Advanced의 핵심은 전체 가중치를 RAM에 올리지 않는다는 점입니다. 모델 전체는 플래시 스토리지에 두고, 프롬프트가 들어오면 라우팅 결정을 먼저 내려 해당 요청에 필요한 routed expert만 선택적으로 로드합니다. 항상 활성 상태인 shared expert가 일관성을 담보하고, 요청당 실제 연산은 1–4B 파라미터 수준으로 유지됩니다[1]. 결과적으로 "20B급 품질, 3B급 메모리 발자국"이 온디바이스에서 성립합니다.

서버 쪽 — Parallel-Track MoE

AFM 3 Cloud는 2세대에서 도입된 Parallel-Track Mixture-of-Experts를 개선해 멀티모달 추론과 긴 컨텍스트 리콜을 강화했습니다. 오디오 이해가 모델 전반에 통합됐고, 이미지 이해는 인간 선호도 기준 +37.8% 개선됐습니다[1]. 전체 만족도는 전 세대 대비 상대 기준 36% 향상입니다[1].

훈련 데이터와 프라이버시 — 공개 정보, 라이선스·구매 데이터, 오픈소스 데이터 혼합으로 훈련되었으며, Apple은 "사용자 데이터는 훈련에 저장되지도, Apple을 포함한 누구와도 공유되지 않는다"고 명시합니다[1].
§3 · 신규

LanguageModel 프로토콜 — 모델 추상화 레이어

이번 세대의 가장 큰 구조 변화[2][5][11]

LanguageModelSession의 백엔드가 공개 프로토콜로 열렸습니다. 기본 제공 구현은 네 가지 — SystemLanguageModel(온디바이스), PrivateCloudComputeLanguageModel(Apple 서버), CoreAILanguageModel(로컬 패키징 모델), MLXLanguageModel(HuggingFace MLX 포맷, Neural Engine/GPU 구동) — 이고, Anthropic과 Google이 런치 파트너로 각자 Swift 패키지를 배포합니다[2]. 

// 어떤 모델이든 세션 코드는 동일하다
let model = SystemLanguageModel()               // 온디바이스
// let model = PrivateCloudComputeLanguageModel() // Apple 서버
// let model = AnthropicLanguageModel(apiKey: t)  // Claude (파트너 패키지)

let session = LanguageModelSession(model: model)
let response = try await session.respond(to: "이 계약서를 요약해줘.")

프로바이더를 직접 만든다면

커스텀 프로바이더는 두 프로토콜을 구현합니다. LanguageModel이 능력 선언 (툴 콜링·guided generation·reasoning 지원 여부)과 설정을 맡고, LanguageModelExecutor가 실제 생성과 와이어 포맷 변환을 맡습니다[11]. 

struct MyLanguageModel: LanguageModel {
    typealias Executor = MyLanguageModelExecutor

    var capabilities: LanguageModelCapabilities {
        LanguageModelCapabilities(capabilities: [.toolCalling, .guidedGeneration, .reasoning])
    }
    var executorConfiguration: Executor.Configuration {
        Executor.Configuration(/* 엔드포인트 · 인증 · 모델 변형 */)
    }
}

struct MyLanguageModelExecutor: LanguageModelExecutor {
    func respond(
        to request: LanguageModelExecutorGenerationRequest,
        model: MyLanguageModel,
        streamingInto channel: LanguageModelExecutorGenerationChannel
    ) async throws {
        // 대화 이력은 타입 있는 Transcript로 도착:
        // .instructions / .prompt / .toolCalls / .toolOutput / .response
        await channel.send(.response(action: .updateMetadata(["modelID": "my-model-2026"])))
        await channel.send(.response(action: .appendText(token)))   // 텍스트 델타
        await channel.send(.response(action: .updateUsage(/* 토큰 집계 */)))
    }
}

프레임워크는 contextSizeExceeded · rateLimited · refusal · guardrailViolation · timeout 등 타입 있는 공용 에러를 정의해 어떤 프로바이더를 쓰든 오류 처리가 통일됩니다. 텍스트가 아닌 출력(인용, 검색 청크, 오디오 등)은 Transcript.CustomSegment로 타입을 유지한 채 트랜스크립트에 남길 수 있습니다[11].

API 키는 바이너리에 넣지 말 것 — 파트너 모델 인증은 OAuth + 키체인 조합이 권장 패턴입니다[2].

토큰 사용량 추적 — response.usage

서드파티 모델이 세션에 들어오면서 비용 추적이 필수가 됐습니다. 응답마다 usage 프로퍼티로 입력·캐시·출력·추론 토큰을 확인합니다[2]. 

print(response.usage.input.totalTokenCount)      // 입력
print(response.usage.input.cachedTokenCount)     // 그중 캐시 적중
print(response.usage.output.totalTokenCount)     // 출력
print(response.usage.output.reasoningTokenCount) // 그중 추론에 쓴 토큰

Private Cloud Compute 개발자 개방

계정 없음 · 키 없음 · 프롬프트 저장 없음[2][4]

지금까지 서버급 LLM을 앱에 넣으려면 프로바이더 계정, API 키 관리, 과금 설정, 프록시 서버가 필요했습니다. iOS 27에서는 PrivateCloudComputeLanguageModel() 생성자 하나로 끝납니다. 인증도 설정도 없습니다 — 기기가 PCC와 직접 신뢰를 협상합니다[4]. 

let model = PrivateCloudComputeLanguageModel()
let session = LanguageModelSession(model: model)

let response = try await session.respond(
    to: "가위가 필요 없는 공예를 추천해줘.",
    contextOptions: ContextOptions(reasoningLevel: .light)   // .light / .deep
)

왜 중요한가 — 온디바이스 3B로 부족한 순간(긴 문서, 복잡한 계획 수립, 깊은 추론)마다 지금까지는 "서드파티 API 계약"이라는 절벽이 있었습니다. PCC 개방은 그 절벽을 없애고, 온디바이스 → PCC → (필요하면) 파트너 모델로 이어지는 연속적인 성능 사다리를 만듭니다. Dynamic Profiles(§6)와 결합하면 단계별로 다른 모델을 쓰는 하이브리드 설계가 세션 하나 안에서 가능합니다.

§5 · 신규

Vision — 온디바이스 멀티모달 입력

프롬프트에 이미지를 첨부한다[2]

온디바이스 모델이 이미지를 이해합니다. 프롬프트 빌더 안에 Attachment로 이미지를 넣으면 되고, 받는 타입은 사실상 전부입니다 — UIImage, NSImage, CGImage, Core Image(CIImage), CoreVideo 픽셀 버퍼, 파일 URL. 크기 제한도 없습니다. 단, 이미지가 클수록 토큰을 많이 소모하므로 contextSize 예산 안에서 관리해야 합니다[2]. 

let response = try await session.respond {
    "이 동물은 무엇인가요?"
    Attachment(uiImage)
}

2025년까지 이미지 → 텍스트 파이프라인은 Vision 프레임워크(분류·OCR)와 LLM을 개발자가 직접 이어 붙여야 했습니다. 이제 "사진을 주고 자연어로 묻는" 흐름이 프레임워크 한 층에서 끝납니다. 영수증 정리, 사진 기반 검색, 스크린샷 요약 같은 기능의 구현 비용이 급감합니다.

컨텍스트 관리 짝꿍 API — model.contextSize로 윈도 크기를 확인하고 tokenCount(for:)로 프롬프트 비용을 사전 계산할 수 있습니다(26.4 도입). 이미지 첨부와 함께 쓰면 "이 사진을 넣어도 되는가"를 보낼 필요 없이 판단할 수 있습니다[2].

에이전틱 — Dynamic Profiles와 시스템 도구

세션 하나 안에서 지시문·도구·모델을 교체한다[2][3]

Dynamic Profiles

에이전트는 단계마다 다른 지시문과 도구가 필요합니다. 지금까지는 세션을 새로 만들거나 모든 도구를 한꺼번에 등록하는 수밖에 없었죠. Dynamic Profiles는 SwiftUI처럼 상태에 따라 body를 다시 선언하는 방식으로 이 문제를 풉니다 — 대화 맥락은 유지한 채, 프로필만 바뀝니다[2]. 

struct CraftProfile: LanguageModelSession.DynamicProfile {
    let states: CraftProjectStates

    var body: some DynamicProfile {
        switch states.mode {
        case .craftAnalysis:
            Profile {
                Instructions { "사진 속 공예 작품을 분석한다." }
                RecordImageAnalysisTool()
                SwitchModeTool(states: states)
            }
        case .brainstorm:
            Profile {
                Instructions { "다음 작품 아이디어를 브레인스토밍한다." }
                BrainstormRecordTool()
            }
            .model(states.privateCloudCompute)   // 이 단계만 서버 모델
            .reasoningLevel(.deep)
        }
    }
}

let session = LanguageModelSession(profile: CraftProfile(states: states))

주목할 부분은 .model() 수정자입니다 — 단계별 모델 스위칭이 선언 한 줄입니다. 가벼운 분류·요약은 온디바이스로, 비용이 큰 추론만 PCC나 파트너 모델로 보내는 하이브리드 에이전트가 프레임워크 관용구가 됐습니다. 멀티 에이전트 워크플로의 기반도 이 구조입니다[10].

셋 다 "직접 만들 수는 있지만 만들기 귀찮아서 다들 대충 만들던" 도구입니다. 특히 Spotlight 도구는 앱 데이터를 시맨틱 인덱스에 넣어두기만 하면(§10) 검색 증강 생성이 공짜로 따라온다는 뜻이라, 로컬 지식 기반 앱의 설계가 근본적으로 단순해집니다[2][19].

디버깅 — 에이전틱 세션의 도구 호출·프로필 전환·토큰 흐름은 Xcode 27의 전용 Instruments로 추적합니다 (세션 243)[15].
§7 · 신규

Core AI 프레임워크

커스텀 LLM을 Apple silicon에 배포하는 정식 경로[8][10]

Core ML이 "일반 ML 모델의 배포 포맷"이었다면, Core AI는 풀사이즈 LLM의 온디바이스 구동을 위해 처음부터 설계된 새 프레임워크입니다. Apple silicon의 유니파이드 메모리와 Neural Engine에 최적화되었고, ahead-of-time 컴파일, 전용 Instruments, PyTorch → Apple silicon 변환 Python 도구를 제공합니다. 새 Siri의 기반 기술이기도 합니다[8][10].

Foundation Models와의 관계가 핵심입니다: Core AI로 패키징한 모델은 CoreAILanguageModel로 감싸 같은 세션 API에 꽂을 수 있습니다(§3). 파인튜닝한 자체 모델을 쓰되 guided generation·툴 콜링·트랜스크립트 관리는 프레임워크 것을 그대로 얻는 구조입니다. 연구용 MLX 모델은 MLXLanguageModel이 같은 역할을 합니다[2].

§8 · 신규

Evaluations 프레임워크

AI 기능의 품질을 단위 테스트 너머에서 측정한다[7]

LLM 기능은 입력이 비결정적이라 XCTAssertEqual로 지킬 수 없습니다. Evaluations는 Apple 플랫폼 최초의 정식 평가(evals) 프레임워크로, 시나리오 집합에 대해 프롬프트·프로필 변경이 정확도에 미치는 영향을 정량화하고 통계적 유의성까지 확인해 줍니다. "프롬프트를 조금 고쳤더니 좋아진 것 같다"를 "정확도 71% → 83%, 유의미"로 바꾸는 도구입니다[7].

세션 335는 이를 "hill-climbing"이라 부릅니다 — 평가 점수를 기준으로 프롬프트를 반복 개선하는 워크플로가 Xcode 안에서 돌아갑니다. 에이전틱 앱용 견고한 평가 설계는 세션 299가 다룹니다[7].

왜 지금 나왔나 — 모델 추상화(§3) 때문입니다. 모델을 갈아 끼울 수 있게 되면 "갈아 끼워도 품질이 유지되는가"를 측정할 도구가 반드시 필요합니다. Evaluations는 그 답입니다.
§9

도구와 생태계

fm CLI · Python SDK · Xcode 27 · 오픈소스[6][8][10]

fm CLI (macOS 27)

터미널에서 온디바이스 모델과 PCC를 바로 씁니다. 셸 파이프라인의 부품으로 LLM이 들어옵니다[6].

$ fm chat                                  # 대화형
$ fm "이 문서를 요약해" < report.md          # 파이프
$ fm "이 이미지에 어울리는 파일명을 지어줘"   # 스크립트 부품

Foundation Models Python SDK

apple_fm_sdk — Swift API와 동형의 Python 인터페이스입니다. ML 파이프라인·노트북·자동화 스크립트에서 Apple 온디바이스 모델을 호출합니다[6]. 

import apple_fm_sdk as fm

model = fm.SystemLanguageModel()
is_available, reason = model.is_available()
session = fm.LanguageModelSession(model=model)
response = await session.respond(prompt="Hello!")

Xcode 27

Anthropic·Google·OpenAI의 모델·에이전트가 IDE에 내장됩니다. 에이전트가 시뮬레이터를 조작하고, 테스트를 작성·실행하고, 크래시를 수정합니다. MCP(Model Context Protocol) 플러그인 확장, Agent Client Protocol 호환, Device Hub, Apple silicon 전용 30% 경량화가 함께 왔습니다[8][10].

오픈소스 전환

Foundation Models 프레임워크 코어가 오픈소스가 됩니다 — Swift가 도는 곳이면 Linux 서버에서도 같은 세션 API로 로컬 LLM을 다룰 수 있습니다. 별도의 Utilities 패키지는 트랜스크립트 관리 프로필, 절차적 지식을 위한 Skill API, Chat Completions 호환 인터페이스를 제공하며 OS 릴리스 주기와 무관하게 업데이트됩니다[2][10].

§10 · 강화

시스템 통합 — Siri · App Intents · 이미지 · 음성

앱을 OS 인텔리전스에 노출하는 통로들[9][14]

App Intents — 새 Siri의 관문

완전히 새로워진 Siri가 앱과 만나는 지점은 여전히 App Intents입니다. 이번 세대의 추가는 세 가지[10][16]:

  • View Annotations API — 화면 위 뷰를 엔티티에 매핑해, 사용자가 "지금 보고 있는 이것"을 Siri와의 대화로 참조·조작
  • Entity / Intent 스키마 — 앱 콘텐츠를 Spotlight 시맨틱 인덱스에 기여. 자연어로 발견되고, §6의 Spotlight 도구(RAG)가 소비하는 것도 이 인덱스
  • AppIntentsTesting — Siri·단축어·Spotlight 실경로를 UI 자동화 없이 검증하는 전용 테스트 프레임워크

Image Playground API

PCC의 전용 이미지 모델(ADM 3)로 재구축됐습니다 — 사실적 스타일을 포함한 고품질 생성, 사진 또는 설명에서 시작, 자연어 반복 수정, 가로/세로 비율 지원. 시스템 시트를 띄우는 것만으로 서버급 이미지 생성이 앱에 들어옵니다[17].

Visual Intelligence · Core Spotlight

앱 콘텐츠를 Visual Intelligence 검색 결과에 노출하는 모범사례가 정리됐고(엔티티 정의, 열기/재생 다이렉트 액션)[18], Core Spotlight는 LLM 검색과 결합돼 앱 데이터의 자연어 발견 경로가 넓어졌습니다[19].

음성 — 시스템 레벨 강화

표현력 있는 음성 합성이 MOS 4.15(기존 3.87)에 도달했고, 받아쓰기의 구두점·대소문자·의미 캡처가 개선됐습니다. 개발자 관점에서는 SpeechAnalyzer(26 도입) 위에 올라간 모델 품질 향상이라 기존 코드가 그대로 좋아지는 종류의 변화입니다[1].

§11

개발자 체크리스트와 샘플 앱

정식 릴리스(2026. 9)까지 두 달, 지금 할 일

  1. Xcode 27 베타 설치 — 27 SDK 없이는 아래 어떤 API도 컴파일되지 않는다
  2. 기존 26 Foundation Models 코드 재실행 — 리빌드된 모델로 품질이 공짜로 오른다. 가드레일 오탐 감소 확인
  3. PCC 무료 티어 검토 — 첫 다운로드 200만 미만이라면 서버 모델이 비용 0. 온디바이스로 부족했던 기능 재설계
  4. 이미지 입력 기능 발굴 — 사진·스크린샷·문서를 받는 앱이라면 §5가 바로 기능이 된다
  5. 에이전틱 단계 분리 — 세션 하나에 도구를 몰아넣고 있다면 Dynamic Profiles로 단계별 재구성
  6. Evaluations 도입 — 프롬프트 수정을 감이 아니라 점수로 관리
  7. App Intents 스키마 채택 — 새 Siri·Spotlight 시맨틱 인덱스·로컬 RAG가 전부 이 위에서 돈다
